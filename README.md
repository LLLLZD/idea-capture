# idea-capture

说完一段话，几分钟后手机里多一篇按体裁成型的稿子。

采集和转写在手机上，成稿在服务端。音频不出手机，服务端只收文本。

## 现在是什么状态

正在做第一阶段：**安卓调试壳 + 服务端**，目标是跑通「录音 → 转写 → 上传 → 拉回成稿」。
iOS 客户端排在第二阶段，设计已经留好位置（转写走设备能力，接口不变）。

## 目录

| 目录 | 内容 |
| --- | --- |
| [`docs/`](docs/) | 设计与验收：[`design/v1.md`](docs/design/v1.md) 是唯一依据；`archive/` 放旧形态留下的结论 |
| [`server/`](server/) | FastAPI + PostgreSQL：登录、模板、提交、出稿、用量 |
| [`phone/`](phone/) | KMP 客户端：共享 UI 与状态机，安卓壳先跑通，iOS 壳后续接 |

## 三个阶段

1. **跑通**：安卓真机能完成一条完整录音到成稿（当前）。
2. **能用**：iOS 端侧转写接上，同事装上能用。
3. **留人**：周汇总、agent 读回、多平台推送（见 `docs/design/v1.md` 的「不做」清单）。

## 旧形态去哪了

上一版是「Speakr + 快捷指令 + 钉钉桥接 + MCP」的组合方案，已整体退役。
还值得留的结论在 [`docs/archive/`](docs/archive/)。老代码在 git 历史里。
