# v1 · 手机端 idea-capture（设计与接口约定）

> 状态：待审。审过之后开 `feat/mobile-v1` 分支动手，本文档是实现与验收的唯一依据。
> 读者：作者本人 + 后续接手的 agent。

## 0. 一句话

说完一段话，几分钟后手机里多一篇按体裁成型的稿子。采集和转写在手机上，判体裁和出稿在服务端，归档在服务端数据库。

## 1. 范围

| 做 | 不做 |
| --- | --- |
| iOS App：登录、首登选模板、录音、端侧转写、上传、看稿 | 网页端、MCP key 管理、周汇总、长期记忆 |
| 服务端：用户 / 模板 / 记录 / 文档 / 用量 / 任务队列 | 多平台推送（钉钉、飞书、QQ）、docx、图导出 |
| 超管 CLI：开用户、重置密码、禁用、配模型、导模板 | 账号自助注册、套餐、计费 |
| 安卓壳（仅用于调试，接局域网 fun-asr） | 安卓正式发布 |

## 2. 拓扑

```
iOS App ──HTTPS──> api-idea.lzdrichard.top (宝塔 nginx, ali-server)
                        │ 反代 127.0.0.1:8892
                        ▼
                   frpc tcp 8892 ──> NAS 127.0.0.1:8892 (FastAPI + PostgreSQL 18)
                                          │
                                          ├─> LLM：现有 OpenAI 兼容通道（复用 Speakr 那把配置）
                                          └─> 库：PostgreSQL 18 @127.0.0.1:5432/idea
安卓调试壳 ──局域网──> fun-asr 0.0.0.0:8030（spark）
```

- 部署形态：`idea-speakr` 用户下 systemd --user + linger，venv，不用 Docker；数据库用 NAS 上现成的 PostgreSQL 18（宝塔装的那套，独立 `idea` 库 + `idea` 角色，不碰 noveldb / loostonesd / memorymanager）。
- 音频永不离开手机；服务端只收文本。
- 环境变量放 `~/.config/idea-server/env`（chmod 600），不进仓库；`DATABASE_URL` 已经在里面，指向 `postgresql://idea@127.0.0.1:5432/idea`。

## 3. 数据模型（PostgreSQL 18）

### users
| 字段 | 说明 |
| --- | --- |
| id | 自增 |
| username | 唯一 |
| password_hash | bcrypt |
| display_name | 显示名 |
| role | `admin` / `user` |
| status | `active` / `disabled` |
| created_at / last_login_at | |

### templates（模板是数据，不是代码）
| 字段 | 说明 |
| --- | --- |
| id | 自增 |
| key | 唯一标识，如 `novel-idea` |
| name | 用户可见名，如「小说思路」 |
| criterion | **一句话：什么时候用它**。模型靠这句做路由，这是模板最重要的字段 |
| skeleton_md | 骨架标题行，如 `## 一句话故事\n## 人物与动机\n…` |
| sample_md | 样例正文，**只给用户看，不进提示词** |
| is_builtin | 通用模板标记（不可取消勾选，用户列表可见） |
| enabled / sort / version | 每次改 content 递增 version |

### user_templates
`(user_id, template_id)` 用户勾选关系。首登必须至少一条（通用模板自动带上，不计入选择）。

### records
| 字段 | 说明 |
| --- | --- |
| id | 自增，内部用 |
| user_id | |
| client_id | 手机生成的 UUID；`UNIQUE(user_id, client_id)` —— 幂等键 |
| raw_text | 转写原文 |
| duration_ms / recorded_at / lang | |
| asr_provider / asr_model | `ios-speech` / `remote-openai` / `debug-manual` |
| status | `pending` / `running` / `done` / `failed` |
| error | 失败原因，人话 |
| created_at | |

### documents
| 字段 | 说明 |
| --- | --- |
| id / record_id | 一条记录可重跑出多份 |
| template_id / template_version | 用了哪个模板的哪一版 |
| genre_reason | 模型给的判定依据（就是现在首行的「— 依据」） |
| body_md | 成稿正文，markdown 明文，**唯一权威源** |
| flags | JSON，如 `{"mermaid_dropped": true}` |
| is_current | 重跑后旧稿置 0 |
| model / token_in / token_out | |

### usage_logs
`(id, user_id, record_id, model, token_in, token_out, duration_ms, created_at)`
**每次 LLM 调用必写一行**，失败也写。这是以后做限额和账单的唯一依据，事后补不回来。

## 4. 接口

```
POST /v1/auth/login            {username,password} → {token, expires_at, user, needs_template_setup}
GET  /v1/client-config         → {asr_presets[], submit_interval_sec:10, min_templates:1, templates[]}
GET  /v1/templates             → [{key,name,criterion,skeleton_preview,sample_md,is_builtin}]
PUT  /v1/me/templates          {template_ids:[...]} → 至少一个，否则 400
POST /v1/records               {client_id,text,duration_ms,recorded_at,lang,asr_provider} → 202 {id,status}
POST /v1/records/status        {client_ids:[...]} → [{client_id,status,error,has_doc}]   ← 批查
GET  /v1/records?cursor=&limit= → 分页列表（标题 = 文档第一节或时间）
GET  /v1/records/{client_id}   → 详情 + body_md
POST /v1/records/{client_id}/retry → 重跑（仅 failed）
POST /v1/records/{client_id}/render-error → 客户端渲染 mermaid 失败时回传，触发一次重跑
```

约定：
- **幂等**：同 `(user_id, client_id)` 重复提交返回已有记录（200），不新建。
- **限流**：每用户 10 秒内最多收一次入库请求，超了返回 `429 + Retry-After`；客户端把 429 读成「已提交，等」而不是报错。
- **异步**：入库即返回 202，worker 跑完再改状态。绝不同步等 LLM。
- **鉴权**：JWT（Bearer），过期 7 天，手机存 Keychain；`status=disabled` 的用户一律 401。

## 5. 提示词组装

1. 取用户勾选的模板 + 内置通用模板 = 候选集（N 条）。
2. 提示词里每个候选只给三样：`name`、`criterion`、`skeleton`。**样例不进提示词**（省 token，也避免模型抄样例）。
3. 模型第一步输出判定：`模板：<key> — <依据>`；第二步按该模板骨架成稿。
4. 通用规则沿用现有 `摘要提示词 v3` 的忠实度硬规则（原话逐字、没定的写未定、不写纪要套话）。
5. 落库时把判定行抽进 `documents.genre_reason`，正文可保留也可渲染时拼。

## 6. mermaid

- 允许模型画图，但限制：只允许 `flowchart` / `sequenceDiagram` 两种；每个图 ≤ 15 个节点；节点文字含空格或标点时用引号包裹。
- 服务端校验（不装 chromium，纯文本层）：解析 `\`\`\`mermaid` 围栏 → 首行是否白名单类型 → 括号/引号配对 → 边语法 `A --> B` 正则。
- 校验失败 → 把错误信息追加进提示词重试**一次**；仍失败 → 删掉该代码块保留正文，`flags.mermaid_dropped=true`。
- 客户端渲染失败 → `POST /v1/records/{id}/render-error`，服务端重跑一次（每记录仅一次）。

## 7. ASR 契约

契约与路由规则统一写在 [第 10 节 语音转写策略](#10-语音转写策略)，这里只补配置来源：

- 服务端只下发 `asr_presets`（地址候选），不保管用户的 key；客户端把选中的 preset 存本地。
- 录音永远由客户端完成，音频不出手机（api 路径只上传给自建转写服务，且可选关闭）。
- `DebugManualEngine` 这类调试桩不进 v1。

## 8. 状态机

```
客户端：recorded(有音频) → uploading → submitted(pending) → done / failed(可重试)
                                     ↘ 断网/429 → queued（本地排队，联网自动重发，靠 client_id 去重）
服务端：pending → running → done
                          ↘ failed(error)
```

UI 要求：`queued` 必须显式可见（一条灰条「等待网络」），否则用户以为丢稿。

## 9. 首登流程

1. 登录（超管预先开的账号）。
2. `needs_template_setup=true` → 模板选择页：给三个预设组合（通用写作 / 技术研发 / 混合），点一下全勾；也可逐个勾。
3. 至少勾一个才能进主页；通用模板固定在列表里、默认勾选、不可取消。
4. 检查 ASR 能力 → 通过就静默进主页；不通过跳到配置页（可以「稍后再说」，但录音前会再拦一次）。

## 10. 语音转写策略

录音永远由客户端自己完成，`feature/asr` 只做「音频文件 → 文本」，不采音、不碰界面、不知道模板与稿子。

```kotlin
enum class AsrRoute { Auto, Native, Api }   // Auto = 原生优先，不可用则降级 api

data class AsrAudio(val path: String, val mime: String, val durationMs: Int)
data class AsrOutcome(val text: String, val used: AsrRoute, val degraded: Boolean)

interface AsrService {
    suspend fun transcribe(audio: AsrAudio, route: AsrRoute = AsrRoute.Auto): AsrOutcome
}
```

| route | iOS | Android |
| --- | --- | --- |
| Auto（默认） | 先 SFSpeechRecognizer，成功即返回 | 原生实现恒返回不支持 → 直接走 api |
| Native | 只走原生，不可用就报错 | 直接报不支持 |
| Api | 直接打 `/asr/v1/audio/transcriptions` | 同左 |

- **降级判据（仅 iOS）**：`SFSpeechRecognizer` 不可用、权限被拒、要求端侧但设备不支持，都算「不可用」并降级 api；识别跑完但结果为空不算失败，不降级。
- **Android 原生实现是空壳**：恒返回不支持，因此 Android 上 Auto 与 Api 等价；这样做是为了 iOS 复用同一份调用逻辑。
- **提交要带实际路径**：`asr_provider` 取 `native` / `funasr`，`asr_model` 取 `sf-speech` / `fun-asr-nano`，落到 `records` 表已有的两列，界面上不打扰用户。
- **路径由用户选**：设置页三选一（自动 / 只用原生 / 只用在线），默认自动；服务端 `client-config` 不下发这个值。

## 12. v1 完成定义（验收清单）

1. 三星上：登录 → 首登选模板 → 录 1 分钟 → fun-asr 转写 → 上传 → 60 秒内看到成稿。
2. 断网点提交：本地排队、显式提示；恢复网络后自动送出，服务端只有一条。
3. 10 秒内连点两次：只进一条，第二次是 200 幂等或 429。
4. 稿子体裁判对 ≥ 8/10（10 条自测语料，含 1 条明显不属于任何已选模板）。
5. 至少一条稿子带 `flowchart` 且手机端能渲染；人为造一条坏图，服务端能重试并降级。
6. 失败可见：错 token / 空文本 / 超长文本，各自有明确失败态和原因。
7. `usage_logs` 里每条记录都有 token 记录（失败调用也有一行）。
8. iOS 真机：同一账号登录、端侧转写、同一份稿子能看（用 iMac 编译装机）。

## 13. 已知风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| NAS 上 LLM 通道抖动 | 出稿排队变长 | worker 超时 120s，失败标 `failed`，客户端可手动重试 |
| 与别的项目共用一套实例 | 连接数、磁盘被挤 | 只用 `idea` 库；连接池上限 10；库里表前缀不必要，但备份独立 |
| iOS 端侧转写质量 | 稿子质量 | 已接受：不额外验证，转写差的多半是口音和专名 |
| 企业证书分发 | 同事装机 | 内部分发，注意证书有效期 |
| 局域网 fun-asr 只限调试 | 不外用 | 定位就是调试路径，不做用户侧承诺 |
